# 借潮而行 · 整体制作框架与执行规范

规范版本：1.1.0-draft.2。更新日期：2026-10-21（初稿 2026-10-20）。适用代码基线：游戏 v0.6.1。

这是可执行的制作规范草案，不是游戏完成报告。用户已确认主要方向，但尚未验收本文全部细节；基准样片、具体数值与公共渲染系统仍待建立。本次只编写文档、索引与规范校验，不实现游戏功能。

## 先读这里

目标是让不同能力的执行模型在同一套结构、组件和证据要求下工作，减少自行猜测美术、临时拼接系统和用特效掩盖造型的问题。规则有优先级、有适用范围、有检查方法；文字长短不等于规范有效。

用户已确认：
- 原鱼的安静海洋气质为主，吸收三个视频的形体、动作、水光联系；不整体转成高密度 MMO 战斗画面。
- 海、岛、船等世界主体是鱼；允许人在岛鱼背上建房、种树，不要求每个杯子和树叶都解释成鱼。
- 岛鱼必须从完整生物结构生成地形；具体体型先保留候选，通过轮廓对照后决定。
- 核心采用带鱼避开捕食者的护送；首版玩法可少，视觉统一、动作流畅与操作可靠不可降低。当前任务是整合规范与交接，关键未定项按依赖点讨论。

## 本次整合：先完成一段漂亮、可靠的护送

最新方向见 D-11 至 D-14。当前核心为：引导鱼群穿过有捕食者的水域，到达安全水域。长远的港湾、岛鱼、钓鱼与能力组合保留，但不再作为验证核心乐趣的前置工程。第 06 章已改写首段体验，并纳入鱼的角色、伙伴保留、旧方法与新鱼、两种归途方案；第 11 章已重排制作依赖。不是另建一份并行玩法规范。

首个可玩切片按工作方案收敛为一个手工水域、灯鱼、一小群普通鱼、一种捕食者、岩体遮挡与一个安全终点。直接控制灯鱼、一个功能伙伴槽等是待样片比较的方案，不是用户逐项冻结的数值。第一段先不带功能伙伴；余辉鱼在基础通过后加入第二次实验。

先读 01、06、09、11、12；制作前补 02、03、05、07、08、10、13。画面、动作、交互与设备各自通过，不能以任何一项抵扣另一项。原有六个视觉基准保留，新增护送基准仍待建立；本次没有运行代码改动或新试玩通过声明。

## 如何使用

先找任务类型，再读取指定章节与规则编号。任务必须声明依据的规范版本、对象卡、参考段落和验收场景。设计提案、实现情况、验证情况、用户评价分别记录，不相互替代。

规范编号的权威正文位于各章节。rules.json 只做位置和场景索引；不能在索引里另造不同的规则。缺失、矛盾或不适用的规则应记录具体位置和影响，不凭一句“整体精美”自行决定。

## 状态警示

当前环境、船、人、岛鱼、灯鱼没有获得整体验收。原鱼的既有造型和游动是用户认可的方向，但正式可复现基准仍需固定版本、视角与证据。v0.6.1 的流程通过不使它自动成为金标准。

现有的“统一材质/灯光/深度/器官状态”尚不是可直接调用的一套完整新 API；第 07 章是目标契约。尚未实现的服务必须先以小范围适配器验证，不能假装它们已经存在。

## 文档校验

在本目录运行：`python validate.py`。校验文件、编号、引用、状态和待定数值。它不运行游戏，不判断画面好不好，也不能授予用户验收。

公共素材库只镜像原创规范和参考元数据，不附三个视频、截图或原鱼源码。具体公开来源和授权未确认的参考只用于分析。游戏运行版本和规范版本分开记录，不能把发布规范称为发布了新版游戏。
