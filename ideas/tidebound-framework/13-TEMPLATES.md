# 13 · 可直接使用的模板与样例

模板用来消除遗漏，不用来增加无效文书。小任务可用简版，但范围、规则、证据和未完成项不能省略。尖括号字段是待填内容，不是现成事实。

## 13.2 已填样例：K-01 旧伪装层的裁切问题

任务 ID：TASK-K01-CULL。目标：镜头拖动时，屏内鱼体及相关场景元素连续存在，不出现与身体脱节的暗色重复轮廓。

规范版本：1.0.0-draft.1。基线：游戏 v0.6.1。实现与验证：待执行。本轮只修该缺陷，不重新设计岛鱼、不修改原鱼字符风格。

范围：检查 src/opening-story.ts 的 reefArt、GUARD_HOME 及可见性分支，必要时修改相关视觉边界适配。保护 src/renderer.ts 与 src/world.ts 的已认可表现；若确需修改，说明原因并扩大对照。

规则：ENG-02、ENG-04、MOTION-03、QA-02、PROC-02。场景：SC-PAN、SC-DEPTH、SC-TURN。参考：REF-FISH；不需要模仿三个视频的新效果。

步骤：
1. 固定同一鱼姿态、相机和种子，记录四边离屏/返回过程。
2. 确认重复暗层的来源和它是否还有剧情用途。
3. 选择移除废弃层，或建立正确实体归属与全视觉边界；记录选择依据。
4. 用相同输入生成前后对照，再检查尾迹、眼口和水下遮挡。
5. 记录修复范围、仍有的问题与实际设备验证状态。

完成条件：问题场景不再因头部离屏让整层跳变；无脱节重复轮廓；原鱼主体与尾迹保持；无新状态/存档改动。若浏览器仍不可用，离线结果可交付，但设备验证保持待验收。这个样例是下一轮任务定义，不是本轮已修复声明。

```text
参数 ID / 作用：

已有值及来源（若有）：

固定的比较条件：
```

一次比较只改变需要判断的少量因素。不要同时改变灯光、鱼大小、镜头与字体后声称某个参数更好。没有证据时保持待校准。

## 13.10 给执行模型的短指令

“读取整体框架 README 的任务阅读路线，再读取本任务卡指定的规则和对象卡。先复现并记录基线。只处理卡中范围，不自行重选风格或补玩法。遇到未定事项查决策表；影响方向的选择与用户讨论，其余可独立工作继续。交付实际证据和限制，不能把编译成功或离线截图称为用户美术验收。”

这段指令需与具体任务卡共同使用；单独粘贴仍不足以保证效果。
