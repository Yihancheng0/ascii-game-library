# 10 · 模型执行流程与任务管理

<a id="PROC-01"></a>
## 10.1 PROC-01：交给执行模型的是有边界的任务包

不能只说“按框架做得精美一点”。任务包必须包含规范版本、用户目标、允许修改范围、保护对象、输入材料、规则编号、对象卡、参数状态、具体产物和验收场景。缺少必要输入时，先查已有记录；确实影响方向再向用户讨论。

较弱模型适合完成：已定结构的一段动作、已定规则的一个材质、可复现缺陷的一个修复、一个边界测试。不要一次交给它“重建整个世界、设计全部玩法、同时优化性能”。拆小是减少自由裁量，不是减少验收。

任务包应能让执行者回答：
- 我在改哪一个对象、哪一个状态或哪一种关系？
- 哪些东西已有基准，不能顺手重做？
- 哪些参数是暂定，怎样作对照？
- 成功的可观察结果是什么？
- 如果失败，应回到哪个阶段？

<a id="PROC-02"></a>
## 10.2 PROC-02：先复现与建立对照，再修改

读取局部职责和现有检查；在干净记录的版本上复现。保存问题场景的前图/片段与输入。不能一开始大幅改名、换渲染体系、整理全部代码，导致无法知道哪个改动修复了问题。

小步修改后只验证相关门槛；通过后再集成。修复公共系统时运行受影响的原鱼、灯鱼、遮挡和交互回归。若改变了设计假设，暂停依赖该假设的工作，更新决策记录；不必停止无关工作。

一个可用检查应在错误版本上失败，在修复版本上通过，或能清楚解释为何采用人工对照。不要写“读取刚写的常量并断言等于它自己”这样的测试。

<a id="PROC-03"></a>
## 10.3 PROC-03：建立经过验证的配方，再扩大生产

理想的复用单位包括：字符材质配方、身体挂点、动作阶段、光照与水纹关联、靠泊转换、交互恢复、证据场景。配方必须带示例、限制和验收，不是从某个对象复制一大段代码。

新增复用模块前，先证明至少一个真实对象受益，再检查第二个对象是否需要同样抽象。避免为了“统一”牺牲原鱼独特效果。遇到不同需求时明确扩展点，不用大量特殊 if 隐藏差异。

给执行模型的参数应有范围来源、默认状态、可调目标和不可破坏项。尚未校准时允许做明确的 A/B 样片，不允许模型随意选一个数后写成正式规范。

<a id="PROC-04"></a>
## 10.4 PROC-04：设计决定集中，执行记录分散

世界观和审美方向写在决策表；规范编号指向唯一正文；每次任务记录自己的实现与验证证据。不要在十份任务报告里各复制一套不同的规则。

变更流程：
1. 写明触发变更的用户反馈或具体缺陷。
2. 标出受影响的规则、对象、参数、存档与基准。
3. 判断是修复实现偏差，还是改变目标。
4. 实现偏差直接在授权范围内修复；重大目标取舍与用户讨论。
5. 更新正文和索引，保留变更记录，再安排依赖任务。

不得通过降低规范要求来让已有实现“过关”。用户明确改变方向时可以修订规范，需记录改变范围，不能反过来以旧规范阻止用户。

## 10.5 常见停滞和正确处理

| 停滞 | 不应做 | 应做 |
|---|---|---|
| 看不出哪里丑 | 无限加细节 | 关闭特效，比较轮廓/明暗/接触 |
| 原鱼不能动 | 顺手重写原鱼渲染 | 先查状态、挂点、碰撞、裁切 |
| 参数太多 | 全部暴露给玩家 | 用基准收敛成少量制作参数 |
| 引导难理解 | 加更多箭头与任务框 | 修正动机、反馈、空间关系 |
| 长文读不完 | 跳过规则自由发挥 | 使用角色阅读路线与任务卡 |
| 视频不可访问 | 猜引擎实现 | 只采用已核实的视觉观察 |
| 浏览器不可用 | 声称全部通过 | 完成独立检查，保留设备待验收 |
| 模型上下文不足 | 凭记忆继续大改 | 读最新交接包和未完任务 |

## 10.6 自查顺序与交接

先检查范围与差异，再检查功能与边界，最后看实际画面。若只改文档，检查链接、编号、状态、公开内容和版本即可；不无意义地重跑全部游戏测试。

结束前写清：最后一个可运行/可校验提交；本轮改变；失败和未验证部分；下一步最小动作；不得触碰的文件；规范版本和参考。新模型先读交接再工作，不能把旧计划当成当前状态。

<a id="PROC-05"></a>
## 10.7 PROC-05：发布与授权分开管理

游戏运行版本、规范版本、素材来源版本分别记录。文档更新不改游戏版本号；发布框架不代表发布新游戏。私有游戏仓库保存开发代码，公共素材库保存原创设计与可公开的元数据。

每次用户授权范围内的更新，完成审查后提交并推送，记录 commit/tag。公共库不上传未确认许可的原视频、截图、第三方源码、玩家存档、凭据或本机绝对路径。框架原创笔记可按素材库许可证复用，第三方作品不因此获得同一授权。

源码主本在游戏仓库 docs/framework；公共库为镜像。只在主本修改，校验后同步；镜像标出主本版本和提交。版本链接必须实际存在，不能先写一个未来链接并声称已发布。

## 10.8 完成定义

一个开发任务完成，需要其范围内产物、相关门槛证据、状态记录和交接都齐全。仅代码能编译、界面有按钮、动画能播放，均不是完整定义。一个规范任务完成，需要内容可用、内部一致、待定项明确、入口可查；不要求在同一轮实现规范描述的所有系统。
