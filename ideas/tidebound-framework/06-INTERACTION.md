# 06 · 玩法、引导、交互与状态

## 6.1 当前核心与长期世界循环

当前核心：观察水域与捕食者 → 聚拢愿意跟随的鱼 → 选择路线、掩护与时机 → 处理掉队或被发现 → 把鱼带到安全水域 → 看见这次行动留下的结果。鱼群是需要照顾的活体，玩家主要管理位置、暴露与队伍状态，不只是牵着一串无碰撞的点走到终点。

“开灯就跟随、关灯就绝对安全”不足以支撑核心。灯改变可见信息，岩体改变视线与通行，捕食者保留短期追踪状态，鱼群需要合法可达的集合点。这些规则形成选择，不靠添加一排技能按钮制造深度。

长期循环仍可加入认识新鱼、形成合作、改变环境和回访港湾。首段不要求先做钓鱼、划船、步行上岛、经营或鳃锁解谜。旧两鱼鳃湾流程保留为后续对象例，不作为新核心的强制教学路线。工作名“夜渡”只指护送切片，项目仍叫《借潮而行》。

<a id="PLAY-01"></a>
## 6.2 PLAY-01：首次体验一次只教一个新的重要关系

首次进入不能同时要求玩家学会划船、上岛、抛竿、能力轮盘、资源兑换和三鱼组合。每一步先有可见动机，再给当前需要的操作。已学操作逐步复用。

当前护送切片的体验节点：

| 节点 | 玩家应理解 | 场景必须提供 | 保留的学习 |
|---|---|---|---|
| 安全起点 | 哪条鱼由我控制，如何游、如何控制灯 | 短输入提示、可试光空间、附近普通鱼的自然回应 | 控制与回应可靠 |
| 初次聚拢 | 有光且可见时，它们会接近并跟随 | 转身、加速、队形靠拢；受岩体遮挡时不隔墙吸引 | 跟随不是瞬移 |
| 看见危险 | 捕食者有巡游和注意目标的不同姿态 | 可观察的巡游路线、发现前兆、掩护位置 | 可以提前判断 |
| 自主过水域 | 等待、绕路、藏好鱼再引开，均由实际规则决定 | 真实空间和一致状态，不按固定点击顺序放行 | 一次有后果的选择 |
| 到达与回看 | 鱼进入了安全水域，我确实带回了它们 | 游入、散开、栖居或继续迁徙；简洁结果反馈 | 这趟行动有可见结果 |

具体键位、鱼数、时长和合格到达比例待校准。首次短提示可以明确“移动、灯、暂停/重试”，不能以审美为由让玩家猜键。教学通过安全空间和低风险首次遭遇完成；不能用无提示的假灯陷阱检验尚未教过的知识。

<a id="PLAY-02"></a>
## 6.3 PLAY-02：每次交互必须定义完整契约

每个交互写明七项：发现线索、接近条件、输入、预反馈、执行中反馈、成功结果、失败或取消恢复。缺少任一项，任务卡不得标为可交付。

后续鳃湾例（不属于首段必做）：灯鱼照向鳃锁。线索来自鳃部不正常水流；玩家靠近后灯鱼关注该部位；输入使光方向稳定；受光结构逐步显露；玩家可中途取消；成功后针鱼有合法作用点；离开再回来仍可重新理解该处状态。

失败应给出因果，不说泛泛的“不能使用”。例如“针鱼仍看不清连接点”可由针鱼退回、连接处未照亮共同表达；必要的短文字辅助解释，但不是唯一反馈。

<a id="UI-01"></a>
## 6.4 UI-01：引导须融入画面，同时保证可读和可发现

主游戏画面避免漂浮的调试圈、方框标签、单字符占位图标和常驻距离箭头。目标附近应优先使用生物朝向、水流、灯光、动作与地标关系。

这不是“禁用文字”。首次操作提示、暂停菜单、字幕、能力说明和无障碍提示可以使用清晰文字。短提示放在稳定安全区域，不盖住目标，不随物体乱跳；图标必须经实际尺寸设计，不能临时用字母充数。

若玩家停滞，可逐层增强帮助：先增强原有世界线索，再给简洁行动提示，再允许查看明确帮助。延迟时间待试玩校准。旧版的约 12 秒回显仅是现有实现事实，不是统一设计定值。

隐藏式菜单必须有可发现入口。键鼠、触控、手柄支持范围应在交付说明中明确，不绘制不可用按键。焦点、失焦、暂停和输入锁定状态需要一致。

<a id="PLAY-03"></a>
## 6.5 PLAY-03：鱼的能力组合必须有规则，不靠任意配方猜谜

每种能力定义输入状态、输出变化、作用范围、前提和代价。组合来自这些属性的交互，例如照明暴露连接点，针鱼作用于可见连接；两种能力不是因为剧情写了“可以”才临时拼在一起。

新组合必须能从此前观察推理。对同类目标的规则保持一致；例外必须有可辨识差异。三鱼组合是后续复杂度，首次教学先展示单一作用，再展示两步配合。

代价不一定是能量条。时间、位置、噪声、灯光暴露、鱼的休息和环境条件都可以，但初版优先少而明确。禁止为了显得有深度同时引入多套消耗货币。

<a id="PLAY-04"></a>
## 6.6 PLAY-04：后续钓鱼有观察、操作和用途，不能只是等待计时

本节仅在后续钓鱼进入制作时生效，不是首个护送切片的依赖。钓鱼应与“人不能直接战胜鱼”的设定协调：吸引、试探、牵引、建立合作比无条件击杀更适合当前方向。是否允许食用、死亡、永久丢失等尚未确认，不能由执行模型自行加入。

大鱼是否吃饵由种类、环境、饵的性质和行为决定，不应因代码只检测小鱼而排除所有大鱼。巨大世界主体也不应被普通钓竿直接拉进背包。体型与捕获/协作方式的边界需作为设计决策。

一次钓鱼至少提供可读的接近行为、咬合/试探信号、玩家的主动选择、拉力或姿态反馈、取消/脱钩恢复，以及结果用途。不能为避免复杂而只加进度条，也不能一上来做高频按键压力测试。

结果应进入已有循环：同行、照明、航行协作、栖居装饰、开路或新的观察信息。具体鱼种的结果写在对象卡；没有用途的收集物暂不扩充。

<a id="PLAY-05"></a>
## 6.7 PLAY-05：任何任务状态都必须能恢复并解释

主任务进度、对象生命状态、空间状态和 UI 提示分开记录。玩家往返、失败、取消、保存重载，不能让提示说“已开放”但碰撞仍关闭。

上岛/下船必须有清晰的靠岸条件、落脚位置和返回路径。码头栈道不可同时成为目标点和阻止靠近的墙。没有有效落点时，保持玩家当前合法状态，不先传送再补救。

同伴丢失、路径阻挡、目标离屏、加载新区域时都有恢复策略。开发演示不能偷偷给玩家任务道具或跳过这些条件，除非入口明确写出演示模式且与真实玩法验收分开。

## 6.8 后续章节的制作门槛

已有长篇剧情与鱼种库继续保留为候选资产。进入制作前，每章需要：一个能被画面体现的核心规律、一段可操作的闭合过程、与前章能力的关系、可复访的世界变化和明确结束状态。仅有台词与任务表不算章节完成。

先解决开场的移动、观察、协作、反馈和返回，再扩展区域。新章节可以提高复杂度，但不能推翻已学规律；每次只增加足以改变策略的少量新内容。具体章节数量与时长不在本规范中虚构承诺。

<a id="PLAY-06"></a>
## 6.9 PLAY-06：护送需要可判断的因果，不能写死过关脚本

第一段工作方案：直接控制灯鱼，只学习移动和灯光；一小群普通鱼、一个可读的冲刺捕食者、一块具有体积的岩体、可藏身的水域和安全终点。键鼠/触控/手柄不一口气全做，先声明一个受测输入方案。自动演示与真正游玩必须使用同一规则、同一碰撞和同一渲染，演示不得把鱼移到安全点或强改敌人阶段。

**灯与鱼群。** 普通鱼只有在适用物种、感知范围、视线和安全条件满足时才响应光；不是所有鱼天生趋光，也不是光照圆内所有鱼立即加入。接近、跟随、丢失线索、搜索或停留是连续可见状态。灭灯后鱼不会凭空消失、瞬停或忘记惯性；已有短期跟随/搜索行为的时长待校准。重新出现的灯须经实际视线与合法路径重聚。

**掩护。** 岩体遮挡光与视线，能否通过取决于身体尺度。安全口袋必须有入口、容量和退路；普通鱼在满足掩护条件时低速停留、保持活动，不能在任意开阔海域凭空获得无敌。灯鱼可以独自离开做诱导，但应看得出哪些鱼留在掩护、哪些仍暴露。首段不新增一个隐藏的“全体锁定”操作。

**捕食者。** 发现来源可为可见灯源或近处可见小鱼，具体感知在对象卡定义。熄灯会减小暴露，却不删除最后看见的位置，不取消已经起势的冲刺，不让捕食者瞬间归位。岩后丢失视线后按有限记忆搜索；没有信息不能实时锁定墙后玩家。先让人读到注意、起势，再出现有效攻击；动作与咬合窗口同步。

**选择。** 设计者至少用两种有效策略通过同一遭遇，例如等巡游空隙与主动引开；不要求每位新玩家都发现两条。可以让路线速度、暴露或带回完整程度不同，但基本完成不能唯一绑定某个诱导脚本。反复开关灯不是禁用技巧；若它不需要看位置就总能清空威胁，应修复感知/记忆/路线设计，不能偷偷重置敌人或临时增加惩罚规则。

**一条可验证的例子，不是唯一答案。** 起点聚鱼 → 把鱼群带进岩后口袋 → 独自亮灯绕到外侧使捕食者注意 → 借岩体切断视线并避开冲刺 → 回来重新聚拢 → 利用空隙通过湾口。每一步能取消、换路线和重试，关卡完成只由实际鱼的到达状态决定。

**失败。** 让玩家能辨认是路线暴露、时机判断或主动冒险导致损失。被导航困住、跟随突然失灵、看不见的攻击和穿墙捕食属于制作缺陷，不能称为难度。首段推荐局部短重试、不永久删除已结识伙伴；具体损失表现、通关最低数量、全员奖励仍待定，开发不得自行决定永久死亡经济。

<a id="PLAY-07"></a>
## 6.10 PLAY-07：被护送鱼、伙伴与敌人分清，关系可以成长

| 本次出行的角色 | 怎么获得/进入 | 玩家怎样使用 | 出行后怎样保留 |
|---|---|---|---|
| 控制对象：灯鱼 | 首段直接可控的工作方案 | 移动与灯光；受身体和水域规则约束 | 不等于正式剧情已决定玩家化身为鱼 |
| 普通护送对象 | 在水域遇见、聚拢 | 保护与引导；不逐条操作 | 活捕分支留居水湾，迁徙分支抵达栖息地 |
| 特殊鱼初遇 | 先作为需理解、需护送的个体 | 它原本就有物种习性，尚非按钮装备 | 达成关系后可成为未来同行伙伴 |
| 已结识功能伙伴 | 后续出行前选择 | 通用的跟随/停驻意图与自身习性 | 关系与可选资格持久保存，无须每关重新捕获 |
| 捕食者/环境鱼 | 水域生态 | 可观察、躲避、诱导，能力作用遵循统一规则 | 不因玩家转镜头就重置行为 |

不是每条被救鱼都送一个技能；同一物种也不因出行角色改变而拥有两套矛盾习性。普通鱼的价值可以是安全抵达和港湾变得有生命，不必全部兑换货币或强度。

**余辉鱼是首个伙伴候选。** 被照亮后短暂存留光，主灯熄灭仍会发亮。第一次遇见，它既会暴露队伍，也能形成临时集合线索；这种能力在成为伙伴之前就存在。随后可以让玩家体验“上次我带它回来，这次它帮我带回别的鱼”。它的准确体型、充光方式、亮度与时长待样片，不可直接当成旧鱼库里的已实现对象。

暂定第二段配装为“灯鱼 + 至多一个功能伙伴”；普通护送鱼不占伙伴槽。所有已结识伙伴保留为可选名单，不默认全队同时出海。这个槽位上限是降低输入和测试复杂度的实验边界，不是永远不变的世界法则。余辉鱼停驻时必须处于合法位置、有活动范围；召回走真实路径，受阻可见且可恢复，不能隐形传送。

伙伴不应因一次试关失败被永久删掉；若以后考虑永久损失，先解决 O-05 并重新审查存档和体验。未选择的伙伴可在归处生活，但首段无需先开发完整基地编辑器。

<a id="PLAY-08"></a>
## 6.11 PLAY-08：新鱼增加选择，旧方法保持有效

“老方法也能过新关”可以是学习的回报。问题是它是否无需观察、总以同一种操作同时获得最快、最安全和最高回报。后续关卡应改变空间与关系，让玩家权衡，而不是凭新物种专属门锁强迫换队。

用余辉鱼比较：开阔水域里灭灯潜行时，它可能增加暴露；有遮挡的岔路里，把它安置在安全口袋可维持集合点，让灯鱼外出诱导。没有余辉鱼时仍可等待、分批或走另一条更保守的合法路线。具体是否支持分批由关卡卡明示，不假设所有水域都有无限等待时间。

一次扩展只引入一种可见差异，先教后组合。建议实验顺序：普通鱼与一次捕食 → 同一规则下的新路线 → 余辉伙伴的收益与代价 → 再考虑听潮鱼对强水动的感知或假灯鱼的诱引。后三者是候选；不得一次全部接入首段。听潮若响应冲刺水动，就应同样响应其它鱼产生的同类事件；不能只监听玩家按钮。假灯必须先给可辨线索与安全观察机会。

每个新鱼提案写清：一条稳定习性；玩家能观察的线索；在哪种处境有利；在哪种处境要谨慎；与至少一种旧鱼/环境的自然关系；无需它的替代办法或明确说明本段只是教学试用。不能只写“获得钥匙、开门、换下一个钥匙”。若新鱼一直不用或永远最优，先比较摆放、代价与路线，不立即堆更多物种修补。

<a id="PLAY-09"></a>
## 6.12 PLAY-09：归途结果真实发生，两种动机保持待比较

用户选择“两种都保留，先比较”。共享护送机制，先比较下面两种末端体验；不是首版同时做两套剧情、经营和结算。

| 方案 | 为什么带鱼 | 为什么到这里就完成 | 持续回报 | 风险 |
|---|---|---|---|---|
| 活捕/留居 | 把鱼带到自己的海水湾，形成可观察的居民群 | 鱼实际游过可读的湾口，进入栖居空间；需要留居机制时让小鱼可通过的鱼篱/地形关系可见 | 返回可看见本次带回的个体，少数可结识为伙伴 | 容易变成刷数量或工具化捕获；不得靠上岸入背包硬切 |
| 救援/迁徙 | 把受威胁鱼群护送到其适宜栖息地 | 穿过狭窄屏障或安全水道到达同类栖地，危险的阻隔有空间依据 | 看见群体安定、环境变化，个别伙伴后续同行 | 容易只剩一次性护送，需验证返回意义 |

终点先作为安全水域，不要求小鱼上岸。禁止用看不见的圆形判定框让鱼在岸边突然消失，或把捕食者在终点边界直接删除。留居方式、终点地形和反向返回要相互一致：鱼篱是否单向、入口能否关闭、如何影响玩家，均在对应关卡卡中定义，不凭一个“安全”标签免测。

抵达按稳定个体 ID 记录，进入、离开、重复进出不重复计数。若允许分批，已抵达个体的安全与结果持续存在；若目标仍可能失效，事先给明确状态与恢复办法。完成后的自由观察、继续接落单鱼或明确结束均需有可用出口，不能被庆祝动画锁住。

比较时用相同核心水域、同样操作与相近美术完成度，仅替换动机、终点表现和归途反馈。观察玩家是否理解、是否关心到达结果和是否愿意再出发。不能凭文字设定替玩家选定收藏或救援；最终选择在制作长期剧情与持久化经济前决定。
