# 07 · 公共系统与工程契约

本章定义目标边界，并非宣称这些 API 已全部存在。v0.6.1 的代码映射见第 11 章。先对现有系统做小范围适配，不要求一次重写整个引擎，也不允许同一个概念在每个对象内再造一套互不相容的实现。

<a id="ENG-01"></a>
## 7.1 ENG-01：对象状态、表现和输入分离

对象定义包含稳定身份、结构、姿态、材质、能力、碰撞和持久状态。输入产生意图；模拟更新状态；渲染读取快照；UI 根据状态解释可执行操作。禁止渲染函数推进任务、UI 标签控制碰撞、演示脚本直接赋值“已完成”。

建议的契约概念（名称可调整）：
| 概念 | 负责 | 不负责 |
|---|---|---|
| ObjectDefinition | 静态结构、材质引用、能力约束 | 每帧位置、剧情奖励 |
| ObjectState | 位置、姿态、行为阶段、持久 ID | DOM 绘制 |
| SurfaceSample | 表面坐标、朝向、深度、材质 | 决定关卡完成 |
| LightState | 光源位置、范围、遮挡条件 | 再画一份独立假灯 |
| InteractionIntent | 目标和玩家意图 | 越过范围直接成功 |
| WorldEvent | 已发生的事实、因果 ID | 替代全部状态存档 |
| RenderSnapshot | 本帧一致的只读表现数据 | 保存游戏或消费输入 |

这些是接口职责，不要求立刻引入 ECS 或更换框架。每个接口需有一个真实对象作为用例，再决定是否抽象；不要先造通用平台而迟迟没有可看的样片。

<a id="ENG-02"></a>
## 7.2 ENG-02：坐标系、挂点与投影必须显式

至少区分世界坐标、分区局部坐标、对象身体坐标、表面坐标、屏幕坐标和字格坐标。函数参数应能看出属于哪一个；转换集中处理，禁止散落相反方向的镜头偏移。

对象上的器官、屋基、栈道根部和装饰绑定稳定挂点。挂点取自本帧姿态，同一帧的碰撞与可见形体不得读取不同时间版本。大尺度移动或原点迁移后，附属物仍保持关系。

投影合同必须记录：世界单位与画面比例、纵横比、相机方向、深度定义、字格尺寸策略和像素比。非等距显示可以保留，但不能不同模块各用一个纵向压缩系数。正式值在基准建立后冻结。

<a id="ENG-03"></a>
## 7.3 ENG-03：几何、材质与缓存各司其职

几何回答“形体在哪里、朝哪、厚度如何”；材质回答“这个表面如何响应光并变成字符”；缓存只复用可复用的计算结果。缓存本身不承担决定美术风格的责任。

缓存键和失效条件必须包含实际影响结果的因素：姿态或形变版本、材质、灯光变化、采样层级、相关字体、时间变化策略。若动态部分在缓存后单独合成，应写明边界。不能为了省事把整对象的动态受光永久烘焙。

可缓存静态结构、字形图集、稳定阴影或分阶段动画。必须说明何时重算、最大占用、淘汰策略和旧结果安全性。禁止每帧无限加入新键，或通过降低更新频率造成肉眼可见的受光跳变。

<a id="ENG-04"></a>
## 7.4 ENG-04：深度、裁切与视觉边界必须覆盖整个对象

碰撞边界、视觉边界、阴影边界和交互范围是不同概念，不能直接复用一个头部包围盒。长鱼、尾迹、灯光、挂件和跨区生物各有完整可见范围。

先做保守可见性判断，再裁切实际片段。鱼头离屏而尾巴仍在屏内时，尾巴必须连续可见；背景掩饰层不能因鱼头返回屏幕而突然整块出现。镜头拖动只改变观察，不能改变世界对象的存在状态。

不透明物体前后关系用稳定深度或明确分层解决。透明、水下透视和发光采用有说明的合成策略。通过降低透明度让穿模“不明显”，不算修复。

<a id="ENG-05"></a>
## 7.5 ENG-05：碰撞、导航、接触与可视身体一致

全身检查覆盖躯干、鳍、尾和必要附属物；不能头避开岸，尾部仍穿过。不同对象可使用不同精度碰撞代理，但需要对照可见轮廓解释误差。

水行、陆行、桥面和上下船使用明确通行层。靠泊点包含船的合法姿态、玩家落脚区和返回区，不能只有一个坐标。路径搜索失败应有恢复状态；禁止反复推挤导致画面抖动。

可变地形先发布一致的新快照，再使角色进入对应状态。若岛鱼呼吸只影响视觉微动，碰撞误差范围必须经过接触镜头校准；达到会影响脚底/水线的程度就必须同步导航或调整动作。

<a id="ENG-06"></a>
## 7.6 ENG-06：共享时间、随机与镜头控制

建立统一模拟步进、表现插值、暂停和恢复策略。具体频率保留现有合适实现并测量，不在文档中随意新定。长帧采用明确的追赶上限或降级方式；不把时间跳跃直接积分进身体结构。

世界生成随机、行为随机和表面微动随机分开。记录种子和版本，保证对照截图可复现；同一种子也不意味着所有鱼同相摆尾。

镜头控制有明确所有者：玩家拖动、跟随、剧情演示按优先级切换，切换有连续性。画面抖动修复需分别检查模拟位置、相机位置、字格采样与 CSS 尺寸，不把所有症状统称为“加平滑”。

<a id="ENG-07"></a>
## 7.7 ENG-07：流式世界与存档必须可重访

自然生成由种子、分区和生成器版本决定；玩家改变使用稳定 ID 的增量数据。卸载时保留需要持久化的状态，重新加载不能重新发奖、重生已救伙伴或恢复关闭的通道。

远坐标采用经过验证的精度策略。原点重定位若采用，必须同步生物、轨迹、镜头、灯光、路径和跨区引用。世界大小不能仅靠把地图坐标上限改大。

存档有 schema 版本、校验、缺省处理和迁移策略。旧档不能静默破坏。演示与验收使用临时存档或单独命名空间，默认不得写进玩家进度。存档敏感数据与本机路径不上传公共库。

<a id="ENG-08"></a>
## 7.8 ENG-08：诊断可见、产品干净

开发覆盖层可以显示骨架、深度、碰撞、挂点、光源、场景阶段、帧耗时和字格。它们必须由明确的开发开关控制，不能混入普通入口或截图后期再裁掉。

一个对象应该能被放进固定种子的小型验收场景，指定姿态、镜头、时间和输入，不依赖手动跑完所有剧情才能检查一块鳃。对照场景不得用不同渲染路径美化对象；专门预置状态需要标明。

日志只记录诊断必要数据，不输出凭据或完整玩家存档。失败报告保存对象 ID、阶段、场景种子和复现步骤。

## 7.9 性能与降级

目标设备、分辨率和帧时间预算待确认。录制帧率不是实际游戏帧率；离线 CPU 画布速度不是浏览器 GPU/DOM 性能。不得在未测设备上写“稳定 60 帧”。

先测模拟、几何采样、字符绘制、合成和 UI 的分项成本，再优化。优先减少远处次要细节、粒子和不必要重算；不通过关闭关键照明、停住同伴或缩掉岛鱼的结构来换取表面帧率。

阶段性交付需记录质量档位及它改变的内容。降级后仍须通过主形、交互反馈、遮挡与存档检查。

<a id="ENG-09"></a>
## 7.10 ENG-09：感知、照明与记忆共享事实，各自解释

光源与地形来自同一世界快照；画面遮挡、鱼的视线和可通行边界不能各造一份冲突的地图。渲染的柔光不等于感知范围：先定义有效光源、实际遮挡、物种感知条件，再决定表面如何表现；不能因为屏幕像素亮就穿墙吸引鱼。相机、缩放、离屏裁切和质量档位不改变感知结果。

捕食者记录目标 ID、最后感知位置、感知时间、行为阶段和合法追踪依据。亮灭改变新的观测，不清空已有记忆。失去视线后只搜索已知范围，不读取墙后真实位置作弊。进入冲刺后按动作契约处理有限转向与中断，而不是随光开关直接切回巡游。

关灯、碰撞、入湾、被捕食与完成可能在同一模拟步发生，必须定义事件顺序或一致的时间比较；同一输入重放在受支持帧率下得到同一关键结果。超长帧不能跳过碰撞与攻击预备。低闪烁模式仅改变表现，不改变事件和威胁；必要信息用形态、朝向或稳定亮度同步保留。

<a id="ENG-10"></a>
## 7.11 ENG-10：护送个体与出行状态可追踪、可恢复

最低状态模型区分：个体身份与物种习性、当前出行角色、感知与移动状态、已到达结果、已结识资格、出行配装、任务阶段。角色不是物种；成为伙伴不凭空改写余辉习性；普通护送数不与功能伙伴槽混在一起。

建议的行为语义为游离、趋近、跟随、受惊、掩护停留、寻找线索、抵达；不要求同名类或某种框架。每种状态须定义进入/退出、路径失败、目标丢失、取消、暂停和重试。导航跟随遵循真实身体可通过的连续路径，必要时重新寻路；不能穿墙跟上、屏外瞬移补队或无限推挤。不可达时保留合法位置并给可理解反馈，便于玩家回来重聚。

检测捕食使用有效攻击阶段与连续移动中的合法接触，至少覆盖高速穿越、小鱼擦边和大鱼转身。视觉身体、碰撞代理和咬合时刻须可对照，不在敌人几何外无理由扣鱼。完成依据实际抵达的稳定 ID，防重复计数、防重载重复解锁、防失败删除已结识资格。

首段可先无跨局存档，但必须明确暂停、失焦、返回、快速重试的语义；不能把临时演示写进旧 harbor 存档。加入第二次出行前，才实现并验证伙伴资格、选择与归途结果持久化。旧档迁移另立任务，禁止在此次文档整合或实验入口中覆盖玩家进度。
