# 01 · 项目总纲、范围与规则效力

## 1. 想交付的体验

玩家进入一个以鱼构成海、岛和船的二维世界。近看能辨认字符如何形成表面；远看能理解造型、体积和场景层次；运动时能看到力量、器官和环境之间的联系。安静、好奇、尺度惊奇与逐渐建立的亲近感是主要体验。强烈效果可用于特定事件，但不能长期占据画面。

玩家通过观察鱼的习性，借一条鱼的能力影响另一条鱼或环境。人的行动是接近、理解、引导、安置与组合。世界要能游玩，不能只靠说明文字讲一个发生在背景里的故事。

“美”是基础工作，不等到任务、地图和数值全做完才补。可玩性同样不能被漂亮录像取代：每个动作必须有可理解的目标、条件、响应与结果。

## 2. 当前与远期边界

| 层级 | 内容 | 现阶段处理 |
|---|---|---|
| 当前制作对象 | 港湾、一个岛鱼局部、船、人、灯鱼、巨鱼、针尾、鳃湾组合 | 建立样板与框架，随后逐项制作 |
| 世界长期方向 | 广阔连续海域、不同生态、鱼作为工具和生活伙伴 | 在结构上容纳，不一次实现 |
| 已保留候选 | 六十种能力鱼、三鱼组合、基因宠物、市场、后续章节 | 保存设计，不算已实装 |
| 历史原型 | v0.4 六章、旧钓鱼与拖航 | 独立保留，未经重制不接入新默认体验 |
| 本次交付 | 规范、模板、参考记录、检验方法、迁移方案 | 不修改运行时表现 |

大世界的尺度不等于优质内容数量。不得用无限复制岛屿、增添章节标题和重复点击事件，宣称完成开放世界。新区域须有自己的可辨地理、行为或关系，并使用已经验证的表达方式。

## 3. 规则效力

<a id="GOV-01"></a>
**GOV-01 · 授权、来源与状态分离。** 用户本次明确指令高于项目文档。项目文档不得要求重复确认已授权的常规修复。用户方向、编辑建议、视频观察、代码事实、已测试结果、用户验收必须分开标注。用户同意某个方向不等于同意所有衍生造型；测试通过不等于艺术通过。

规则用词：
- **必须 / 禁止**：本规范的硬约束；任务需要改变时须登记理由与影响。
- **应**：默认做法；可以用具体证据提出更合适的方案。
- **候选**：允许比较，尚未决定。
- **暂定参数**：用于实验，不自动升级为永久标准。
- **待确认 / 待测量**：不允许伪装成已有结论。

<a id="GOV-02"></a>
**GOV-02 · 分层通过，不可互相抵偿。** 形状 → 体积与空间 → 字符材质 → 动作 → 环境响应 → 场景整合 → 完整交互。前一级不成立时，只能回到对应问题处理；不得增加粒子、字幕、光圈或支线来冲抵。发现前级缺陷可以退回，不机械追求每阶段都重新从头做。

<a id="GOV-03"></a>
**GOV-03 · 成果与证据使用独立状态。** 一项对象至少记录 design、implementation、behavior_validation、visual_review、user_acceptance。implementation=implemented 不能自动改变其他字段。没有真实浏览器验证则写 unavailable 或 pending，不能用离线录像填 passed。审查也注明由作者自查、独立评审还是用户试玩完成。

<a id="GOV-04"></a>
**GOV-04 · 新旧规则有明确作用域。** 本框架用于后续制作；旧版文档保留历史实现和决定。在字符尺度、缓存技术与柔光问题上，以本框架的结果标准取代旧的笼统禁令。正式未决项由第 12 章管理；不同文件不得各自确定不同答案。

## 4. 冲突时的处理

先找最具体且最新的用户要求，再看已记录的决策。如果只是实现细节，可以在当前授权范围内选择并说明。若涉及改变整体风格、岛鱼类型、玩法方向、用户数据或扩大范围，应把选择、差别、受影响内容整理后讨论。

不能通过降低标准来消除失败：例如模型做不出完整锁鳞，于是把“单字符可识别”改成达标；或者浏览器无法使用，便删除浏览器检查。正确记录是“此项尚未验证”或“需要补充公共能力”。

## 5. 能力一般的执行模型如何受益

关键造型先由完整设计与样片确定；后续模型使用材质、动作和场景配方，不每次从头发明。它应能回答：当前目标是什么、允许改哪里、不能改变什么、如何证明结果、遇到什么要停止猜测。

不要求每个小任务都读全部文档。任务包给出所需片段、编号、对象卡、已批准基准和检查场景。若没有正确的样板，模型只能产出候选，不能自行评为最终资产。

## 6. 本框架明确不承诺

不能通过纯文本保证所有模型都具有成熟审美；不能从短视频推断对方源码和实现成本；不能用统一字符滤镜自动统一世界；不能把单个视角的漂亮截图等同于完整游戏。这个体系提供可重复的约束、比较和修正路径。
