# 借潮而行 · 后续研究交接

交接版本：1.0｜2026-10-20。用途：让新线程直接继承项目决定、证据与限制，继续研究。新线程的首次任务是读取与研究，不自动启动游戏重做；具体开发按用户后续指令进行。

## 1. 先知道这四件事

1. 游戏运行仍为 v0.6.1；近期长篇框架、审阅卡、密度对照均未修改游戏运行代码。
2. 原鱼的造型、游动、微光与尾迹是用户认可的审美方向。环境、岛、船、人、灯鱼和整体交互尚未得到正式效果验收。
3. 用户已读完八张作者审阅卡，并认可所有“我的建议”。权威范围见整体框架第 12 章 D-10。不要把八个方向再逐条问一遍，也不要替开放问题选答案。
4. 需要先用严格框架、成熟参考、对象样片与实际操作建立质量，再扩展内容。用户已经多次因粗糙与不可玩而失望，不希望靠其反复发现基本缺陷。

## 2. 必须保留的方向

- 二维 ASCII 海洋，原鱼的安静气质为主，学习三个视频的形体、动作、水光联系。
- 海、岛、船等世界主体是鱼；人可以在岛鱼背上建房种树，不要求所有建筑植物都是鱼。
- 岛鱼从完整身体形成地形，不能给普通岛加眼睛。具体物种尚未选择；宽背、覆岩、弯身只是候选。
- 人借鱼对抗鱼；能力具备可观察规律、作用条件和组合关系。首次合作先少量配合，逐步增加复杂度。
- 画面海上疏、停靠处较丰富；环境细节不抢鱼。近期密度对照用户觉得差异不明显，表示如果左边更简单就用左边；记录为简单优先的疏朗暂选，不是美术效果通过。
- 各种材质以各自方式活动，避免满屏跳字。鱼保留原有闪烁。
- 岛鱼逐渐显露：先感觉港湾活着，再看懂器官与整体，早期有清楚线索。
- 鱼伙伴有生命感且可靠；个性来自动作反应，暂不堆养成数值与频繁气泡表演。
- 引导由世界线索与必要短提示共同承担，首次按键清楚、帮助逐层增强；不能用“干净”让玩家完全猜操作。
- 钓鱼有观察和主动选择，结果进入探索与生活。先做好一个港湾和一个不同的新场所；返访保留世界改变，安静航行与短暂奇观交替。

## 3. 不应从认可中推断什么

八项建议获认可，不等于当前样稿精美、全部游戏流程好玩、岛鱼或船鱼物种已定、所有数值已校准。具体体型、船鱼操控、死亡与永久失去、食用鱼、奖励优先级、平台性能、声音、章长、天气频率仍有未定项。

原鱼方向获认可，不等于 v0.6.1 整张画面是合格环境基准。目前正式视觉基准 accepted 数量仍为 0。

## 6. 研究如何继续才有用

建议首先研究一个可比较的对象与一个空间问题，不直接重做整游戏：
1. 固定原鱼与问题场景基准，查明当前采样、坐标、深度、挂点怎样连接。
2. 围绕一个岩体/一段岸/灯鱼或船鱼制作研究提案，说明从参考借什么关系、如何保留原鱼风格、用什么片段验证。尚未获开发指令时先提交证据与方案。
3. 岛鱼候选同机位、同光线、同采样尺度比较；不要一版精雕、另一版草稿陪衬。
4. 首次协作检验完整的观察—尝试—可恢复失败—成功—回访，不能只放成功动画。

若进入开发，框架依赖为 M0 基准 → M1 空间稳定 → M2 视觉配方 → M3 岛鱼结构 → M4 开场闭环 → M5 天气/边界/一个新区 → M6 扩章。可按用户新指令调整，但需解释依赖，不能用功能数量盖住基础失败。

## 8. 工程、验证与发布边界

- 原鱼 src/renderer.ts、src/world.ts 的轮廓、银灰体积、稀疏彩色微光、尾迹需要保护性对照；尽量从外围适配修问题。
- 缓存、精灵、建模辅助不是一概禁止；最终应通过字符形体、体积、受光、接触、动作和交互检查。
- 新的共享材质/照明/深度/挂点 API 是目标契约，不是已经存在的完整平台。
- v0.6.1 有历史类型/构建/行为/存档与离线真实输入证据。离线约 84.4 秒、20fps 输出不代表真人时长或浏览器帧率。
- 浏览器工具此前在应用设置中关闭；新线程按当前工具状态检查，不绕过限制。离线验证与浏览器/设备/UI/美术验收分别记录。
- 当前存档 tidebound-harbor-v2；保留 v1 与旧档，演示使用临时状态，不写正常玩家进度。
- 运行变化按任务执行相关检查与实际画面；文档变化只作对应校验，不假装做了新一轮游戏回归。
- 源码私有；原鱼上游未识别授权，不随公共库 MIT 重新公开。ASCII Magic 的 MIT 声明保留。用户视频和截图不发公共库。
- 每次授权更新保存变更、限制、证据、提交/标签；规范版本与游戏运行版本分开。公共镜像从私有规范主本同步。
